# 06 — Creator feedback log

Real feedback from the creator on past episodes. Treat each as a rule.

| Feedback | Rule |
| --- | --- |
| "Font / color scheme looks very AI created." | Use the restrained palette and Helvetica/Avenir. No neon, gradients, glows. |
| "Remove unwanted silences." | Always cut dead air and pauses via `edit.json`. |
| "Make this mobile friendly." | Portrait 1080×1920, large type, safe zones respected. |
| "Make it more animated… show a request coming in and a defense scrubbing." | Show the mechanism as motion, not as a labeled diagram. |
| "Text on screen should be low." | Heading + short labels only. |
| "No overflow in the boxes." | Size chips/cards for their labels; verify with stills. |
| "Humanize the defense. Keep the same character everywhere." | Defenses are characters (bouncer, detective) and stay consistent. |
| "The bouncer looks like a detective initially." | Baseline and method must be visually distinct at first glance. |
| "Sync can be better when we say … a tool output / webpage." | Animate list items one by one on their words. |
| "Title + tagline is a lot of text for phone." | Heading only; no taglines. |
| "Do we need the image from the paper here? Animate, don't add slides." | Paper screenshot once; everything else animated. |
| "Clear as water on mute… cartoons." | Characters + story; captions carry narration. |
| "We actually sanitize that output. Confirm with the paper." | Visuals must match the paper's exact mechanism. Read the PDF. |
| "Captions can start after the title screen." | Captions filtered to after `titleCardMs`. |
| "Call the website 'Malicious website'." | Name dangerous inputs plainly for what they are. |
| "It was not clear that bread thing was the agent." | Label non-obvious characters (agent has a name tag). |
| "Whitespace at the bottom… adjust for Instagram/LinkedIn." | Layout follows app safe zones (see 03-visual-system). |
